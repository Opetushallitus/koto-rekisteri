# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kielitutkintorekisteri (kitu) — OPH's register for language-exam data. Virkailija-facing Spring Boot app that also forwards records to the KOSKI service so they can be shown to citizens in Oma Opintopolku. Primary documentation and external API descriptions are linked from `README.md`.

## Toolchain

All language/tool versions live in `.mise.toml` and are installed automatically by `scripts/start_local_env.sh`. Java 25 + Kotlin 2.3.21, Node 24, Maven 3.9, ktlint, prettier, shellcheck, aws-cli, esbuild, humanlog. `AWS_PROFILE=oph-ktr-dev` and `SPRING_PROFILES_ACTIVE=local` are set by mise.

## Common commands

```shell
# One-shot dev env setup (installs mise deps, Playwright browsers, starts tmux with db+server).
# Pulls secrets from AWS Secrets Manager via the oph-ktr-dev profile.
./scripts/start_local_env.sh
./scripts/start_local_env.sh --setup-only   # skip tmux/containers

# Run the server standalone after the DB is up (wraps mvnw spring-boot:run + humanlog).
./scripts/start_local_server.sh

# Just the DB + Jaeger
docker compose up -d

# Backend build/test (in server/)
./mvnw package               # full build with tests
./mvnw test                  # tests only
./mvnw test -Dtest=OidTest   # single test class
./mvnw test -Dtest=OidTest#methodName

# Formatting (ktlint + prettier + shellcheck). CI runs the same script.
./scripts/check-formatting.sh
./scripts/format.sh          # auto-fix

# E2E Playwright (in e2e/)
npx playwright test
npx playwright test --ui
TEST_WORKERS=4 npx playwright test   # max 4

# Infra (in infra/)
npm run diff/dev
npm run deploy/dev
TAG=$(git rev-parse HEAD) npx cdk deploy 'Dev/**'
```

Backend tests spin up PostgreSQL via Testcontainers — Docker must be running. The Playwright suite expects the app's Maven build to launch it; see `e2e/README.md` for how to attach to an already-running IDEA debug session (`reuseExistingServer: true`).

## Architecture

### Layout

- `server/` — Spring Boot 4.1.0 + Kotlin backend. Source roots are `src/main/kotlin` and `src/test/kotlin` (configured in `pom.xml`, not the Maven defaults). Packages under `fi.oph.kitu/` are organized by **feature domain**, not by layer.
- `infra/` — AWS CDK (TypeScript) app. `bin/infra.ts` wires four stages: `Util` (shared ECR repo + GitHub Actions roles), then `Dev`/`Test`/`Prod`. Each env stage composes stacks (`service-stack`, `db-stack`, `network-stack`, `alarms-stack`, `bastion-stack`, `backups-stack`, `koski-audit-logs-integration-stack`, ...). Deploys pick the container by `TAG` env var.
- `e2e/` — Playwright tests against a real server + Postgres.
- `scripts/` — bash helpers for local env, AWS profile/secret setup, tmux orchestration.
- `docs/` — published to GitHub Pages (DB schema diagrams via SchemaSpy, component UML per environment, db-scheduler docs).

### Feature domains (server packages)

Each domain typically contains its own `*ApiController`, `*ViewController` (server-rendered HTML via `kotlinx.html`), `*Service`, `*Repository`, entities, and `*ScheduledTasks`:

- `vkt/` — Valtionhallinnon kielitutkinnot
- `yki/` — Yleiset kielitutkinnot (suoritukset + arvioijat, with a CSV import pipeline)
- `kotoutumiskoulutus/` — integrates with the Koealusta kielitesti service
- `koski/` — outbound integration to KOSKI
- `ilmoittautumisjarjestelma/` — outbound integration to the exam-registration system
- `oppijanumero/` — Oppijanumerorekisteri client
- `organisaatiot/`, `koodisto/`, `yhteystiedot/` — reference-data clients
- `auth/`, `oauth2client/` — CAS + OAuth2 (OPH virkailija SSO)
- `observability/`, `auditlogs/` — OpenTelemetry + ECS-formatted structured logs
- `csvparsing/`, `tiedontuontischema/`, `koodisto/`, `html/`, `i18n/` — cross-cutting utilities

### Cross-cutting pieces worth knowing

- **DB & migrations**: Spring JDBC (no JPA entity manager) over Flyway. Migrations in `server/src/main/resources/db/migration` (`V*__*.sql`). Schema docs are generated by `docs/build.sh` via SchemaSpy. The V-numbering has gaps (V7, V38, V46–V55, V65) left over from earlier mistakes — most notably V65 was renamed to V67 to repair an out-of-order deploy (commit `04b1d07d`). Don't reuse skipped numbers; just continue past the highest.
- **Scheduled work**: uses `db-scheduler` (kagkarlsson). Tasks are enabled/disabled per Spring profile via properties (`kitu.yki.scheduling.*`, `kitu.vkt.scheduling.*`, etc.). There's a db-scheduler UI mounted by the app; see `docs/db-scheduler/README.md`. The `db-scheduler-log` add-on is **vendored** at `server/src/main/kotlin/io/rocketbase/extension/` (port of 0.7.0 with SB4 package relocations) until an upstream SB4-compatible release exists — see the package README for the rollback procedure. Schedule strings go through `ExtendedSchedules.parse` (`util/scheduling/`): it accepts the built-in forms (`FIXED_DELAY|Ns`, `DAILY|HH:mm`, `-`) and falls back to **SPRID53 cron** (6 fields `sec min hour dom month dow`, `?` allowed, **no year field** — Quartz-style 7-field crons fail). **Gotcha for "manual"/on-demand tasks:** a `-` (disabled) schedule does **not** make a task that's triggerable from the UI — db-scheduler deliberately never creates a `scheduled_tasks` row for a disabled recurring task (and removes any existing one) in `ScheduleRecurringOnStartup`, and the UI lists only existing executions, so the task is invisible with no "Run now". To get a UI-triggerable-but-effectively-never-auto-running task, give it a rare real cron (e.g. `0 0 0 29 2 ?` = leap-year Feb 29) rather than `-` — see `kitu.yki.scheduling.anomalyCheckFullYear.schedule`.
- **JSON**: Jackson 3 (`tools.jackson.*` packages, e.g. `tools.jackson.databind.json.JsonMapper`). Annotations still come from `com.fasterxml.jackson.annotation` (kept for backward compat). `JavaTimeModule` no longer exists — register `java.time` serializers via `SimpleModule()`. `ObjectMapper.copy()` is gone — use `.rebuild()...build()`. Accessor renames on `JsonNode`/`JsonParser`: `textValue()` → `stringValue()`, `asText()` → `asString()`, `p.text` → `p.string`. Custom deserializers should extend `ValueDeserializer<Any>` for `@JsonDeserialize(using = ...)` compatibility.
- **Config & profiles**: `application.properties` is the base; per-env overrides in `application-{local,local-opintopolku,untuva,qa,prod,e2e}.properties`. `ConditionalOnNonEmptyProperty.kt` is a custom condition used to wire beans only when a config value is set.
- **Secrets**: never hard-coded. Local dev pulls from AWS Secrets Manager via `scripts/ensure_aws_secrets.sh`. The README lists which secrets must exist manually per AWS account (`slack-webhook-url`, `oppijanumero-password`, `kielitesti-token`).
- **Frontend**: server-rendered HTML built with `kotlinx-html-jvm`; styling via Pico.css + a small `style.css`. Client-side JS is bundled with esbuild. No SPA.
- **Localization (i18n)**: FI/SV/EN. `LocalizedString(fi, sv, en)` (`i18n/LocalizedString.kt`) is the multilingual primitive for **both** koodisto reference data (loaded fi/sv/en from the koodisto service via `Translations`/`LocalizationService`) and static UI chrome. UI chrome lives in the typed catalog `i18n/UiText.kt`, where each entry is `tr("dotted.key", fi = "…")` — a computed getter (or a function that `.interpolate("count" to n)`s a `{count}` placeholder for parameterized strings). **Finnish is the canonical default in code**; Swedish/English are sourced at runtime from **Tolgee** via OPH's lokalisointi proxy (see "Tolgee sourcing" below). **No** Spring `MessageSource`/`messages*.properties` — do not add them. `LocalizedString.get(lang)` returns the requested language, **falling back to `fi`** (then the literal `"<invalid LocalizedString>"`) when that language is missing — so a half-migrated page renders untranslated bits in Finnish rather than blank; this is what makes package-by-package migration safe. `toString()` resolves the **ambient** `CurrentLanguage` (it is defined as `get(CurrentLanguage.get())`), so plain string interpolation and `+` emit the current UI language. The active language is resolved **ambiently**, not threaded: a `CookieLocaleResolver("kitu_lang")` + `LocaleChangeInterceptor(paramName="lang")` (`i18n/LocalizationConfig.kt`, bean **must** be named `localeResolver`) sets Spring's `LocaleContextHolder`, and `CurrentLanguage.get()` (`i18n/CurrentLanguage.kt`, a plain `object` — **not** a `@Service`, to avoid the `@WithSpan` CGLIB trap) reads it, defaulting to FI when no request is bound. Renderers emit a translated string by writing `+someLocalizedString` directly inside a tag block (e.g. `strong { +it.title }`), via the sole helper in `i18n/HtmlLocalization.kt`: `operator fun LocalizedString.unaryPlus()`. It's a `context(tag: Tag)` function — this is why `pom.xml` enables the `-Xcontext-parameters` Kotlin flag — and, like any extension, it must be **imported** (`import fi.oph.kitu.i18n.unaryPlus`) in each file that uses it. (There is deliberately no `t()`/`l()` helper and no Spring `MessageSource`; if you need the raw `String` — e.g. for an HTML attribute — call `someLocalizedString.toString()` (which resolves the ambient `CurrentLanguage`; pass an explicit `.get(lang)` only when you need a specific language).) `object`/static-`val` renderers (`html/Page.kt`, `html/Navigation.kt`) need no signature changes. The `html/Common.kt` article helpers are named **`errorMessage(LocalizedString)` / `warningMessage(LocalizedString)`** — not `error`/`warning` — precisely because a `FlowContent.error(String)` would let an accidental `error("literal")` silently resolve to Kotlin's stdlib `kotlin.error(Any): Nothing` (throws at runtime) instead of rendering an article. Keep those names distinct from `kotlin.error`. Wrap fi-only text as `LocalizedString(fi = "…")` during incremental migration. **Tolgee sourcing:** `tr(key, fi)` returns `LocalizedString(fi = <code default>, sv/en = TolgeeMessages[key])`; when the store is empty or a key/locale is missing, `get()`'s fi fallback yields Finnish. `TolgeeMessages` (`i18n/TolgeeMessages.kt`) is a plain `object` store filled at startup by `LokalisointiLoader` (an `ApplicationRunner`) which calls `LokalisointiClient` — it GETs flat per-locale JSON `/lokalisointi/tolgee/{namespace}/{locale}.json` from `https://{opintopolkuHostname}` and merges fi/sv/en into `Map<key, LocalizedString>`. `LokalisointiScheduledTasks` re-fetches on a db-scheduler interval (`kitu.lokalisointi.scheduling.*`). The **entire** lokalisointi machinery (client, RestClient config, loader, scheduled task) is gated by `@ConditionalOnNonEmptyProperty("kitu.lokalisointi.namespace")` — set only in untuva/qa/prod (`namespace=kielitutkintorekisteri`; the Tolgee **namespace** separates each app's translations in the shared lokalisointi service, cf. KOSKI's `koski`); in test/e2e/local the beans don't exist and the store stays empty, so everything renders in the in-code Finnish. Fetch failures never fail startup (the loader `runCatching`s and logs). No secret — the proxy serves published files. **Seeding Tolgee:** `tr` also records each `key→fi` into `UiTextRegistry`; `UiTextWarmup` (an unconditional `ApplicationRunner`) reflectively invokes every `UiText` property + single-`Long` function at boot so the registry is complete regardless of what's been rendered. `LokalisointiController` exposes `GET /kielitutkinnot/lokalisointi/puuttuvat-kaannokset` (virkailija auth) returning `{key: fi}` for keys **not yet in the `TolgeeMessages` store** — pull it and import into Tolgee under namespace `kielitutkintorekisteri` (language `fi`) to seed/complete the keys; it shrinks to `{}` as Tolgee fills. Gotchas: (1) `Navigation.mainNavigation` **must stay a computed `val … get()`** (not a stored `val`): it references `UiText.Nav.*`, and a stored `val` would freeze those at class-load (before Tolgee loads), pinning the nav to Finnish; the getter rebuilds the list per render so it picks up loaded translations. (2) Table/CSV column headers are `DisplayTableEnum.uiHeaderValue: LocalizedString` (not `String`), resolved via `CurrentLanguage` in **both** the HTML table and `DisplayTableCsvRenderer` — so CSV **follows the UI language** (the old `.language(Language.FI)` pin in `VktSuoritusService.findEnrichedForCsv` was removed). If you ever need a fixed-language CSV again, re-pin `.language(...)` on the `translationBuilder()`. (3) There is no language-switcher UI yet — selection is wired via the OPH virkailija-raamit later; the `?lang=`/cookie plumbing already works. Migrated to `UiText` so far: shared chrome (`Page`, `Navigation`, `ErrorPage`, `ErrorsArticle`, `Time`), the shared table/filter/CSV framework (`html/table/*`), the **`vkt`, `yki`, and `kotoutumiskoulutus` suoritukset views** (pages, column headers, filters, infoTable labels), and the koto **tehtäväpankki** pages (`kotoutumiskoulutus/koealusta/tehtavapankki/*` — incl. the ~32 Moodle question-type + ~34 metadata + language-name labels; the `moodleTehtavatyyppiNimet`/`languageLabels` `mapOf` lookups were rewritten as call-time `when`-functions returning `UiText.Koto.*`, since a top-level `val` map would **freeze** the translations at class-load). **Enum display values are localized too**, via the same class-load-freeze fix: `Arviointitila`/`TutkinnonOsa` `viewText` and `VktArvioinninTila` `nimi` were changed from enum-constructor `val`s to **computed `get() = when(this){ … -> UiText.X }.toString()`** properties (call sites reading `.viewText`/`.nimi` are unchanged), and `YkiViewController.ONR_UNAVAILABLE_WARNING` became a computed `val get()`. **This `when`-getter is the standard recipe** for any enum/companion display `val` you want translated. Still hardcoded Finnish, deliberately: `*ApiController` OpenAPI + API-response error strings (external-API audience); `Arvosana.arvosana` (a `@get:JsonValue` **serialization** value, not pure display — must stay a fixed string); and koodisto `nimi` (loaded multilingually from the koodisto service via `LocalizationService`/`Translations`, a separate mechanism).
- **Typed errors**: Arrow's `arrow.core.Either<E, V>` (left = error, right = value) is the project's convention for propagating domain errors out of services — prefer returning `Either` over throwing. Project-specific helpers live in `util/result/EitherExtensions.kt` (`getOrThrow` and `splitIntoValuesAndErrors`). `Either.fold(ifLeft, ifRight)` (note: ifLeft is the **first** named arg, opposite of the legacy `TypedResult.fold(onSuccess, onFailure)` order — always use named args).
- **Validation**: validators implement `Validation<T>` (`util/validation/Validation.kt`) — a three-phase pipeline of `validateBeforeEnrichment` → `enrich` → `validateAfterEnrichment` run by `validateAndEnrich`. The two `validate*` phases use the `ValidationRaise` typealias (= `Raise<NonEmptyList<ValidationError>>`) as their receiver and return `Unit` — the type system thus prevents transforming the value inside them. The sibling typealias `ValidationResult<T> = Either<NonEmptyList<ValidationError>, T>` covers the Either-shaped result. All transformation/derivation lives in `enrich` (no `Raise` receiver, cannot fail). Checks that depend on the post-enrichment shape go in `validateAfterEnrichment` — see `YkiSuoritusValidation` where `enrich` filters out non-attendance osakokeet and `validateAfterEnrichment` then enforces "at least one osakoe" against the filtered list. Compose sub-validators inside an `accumulate { … }` block (from `arrow.core.raise.accumulate`, `@OptIn(ExperimentalRaiseAccumulateApi::class)`), wrapping each call in `accumulating { … }` so all errors are collected in parallel rather than short-circuiting. Use `mapOrAccumulate` over collections, and `ensure` / `ensureNotNull` for predicates. Sub-validators that themselves accumulate take `RaiseAccumulate<ValidationError>` and nest further `accumulating { … }` blocks inside. Controller boundary uses `validation.validateAndEnrich(…).getOrThrow()` (extension in `ValidationService.kt`) which throws `ValidationException(NonEmptyList<ValidationError>)` — caught by `GlobalControllerExceptionHandler` and turned into a 400.
- **Observability**: Spring's `spring-boot-starter-opentelemetry` + an explicit `opentelemetry-spring-boot-autoconfigure` dep (the latter supplies the `@WithSpan` aspect that Spring's starter drops). Traces exported OTLP to Jaeger locally (`docker-compose.yml` exposes UI on `:16686`). **Gotcha:** `@WithSpan` makes the bean a CGLIB proxy. A `@WithSpan` method **inherited from an abstract base class** reads that base class's constructor-injected fields as `null` at runtime (the proxy delegates the call in a way that skips the base-class field init), even though the same method+field on the concrete `@Service` works fine. So don't push injected dependencies (`Tracer`, repositories, `AuditLogger`) into an abstract base service — keep them on the concrete class and extract shared logic into top-level helper functions that take the deps as params (see `csvparsing/CsvExportErrorHelpers.kt`, used by `Yki*ErrorService`).
- **RestClient message converters**: configure via the SB4 DSL `configureMessageConverters { cs -> cs.registerDefaults()... }`, not the deprecated `messageConverters(...)`. Use `withJsonConverter(JacksonJsonHttpMessageConverter(mapper))` to swap Jackson, and `configureMessageConvertersList { list -> list.add(0, x) }` when ordering matters. Any `RestClient` that reads a JSON body into `String` (including `retrieveEntitySafely(String::class.java)`) must call `.withLenientStringConverter()` from `restclient/RestClientExtensions.kt` — Spring 7's default `StringHttpMessageConverter` only advertises `text/*`, so without the helper the call fails inside Jackson.
- **Spring HATEOAS 3 `linkTo` DSL**: tracks the controller invocation via the lambda's **return value** (not a thread-local), so the lambda signature must be `(C) -> Any`. A `C.() -> Unit` receiver lambda collapses to `Unit` and bypasses the proxy's `LastInvocationAware` tracking — see `html/Navigation.kt`.
- **Testcontainers 2.x**: artifacts are prefixed (`testcontainers-postgresql`, `testcontainers-junit-jupiter`) and `PostgreSQLContainer` moved to `org.testcontainers.postgresql.PostgreSQLContainer` (no generic parameter). On macOS set `DOCKER_HOST="unix://${HOME}/.docker/run/docker.sock"` if the socket isn't auto-detected.

## Conventions

- **Language**: user-facing text, commit messages, and PR titles are in Finnish. Kotlin/TS identifiers are Finnish/English mix following existing usage in the touched package — follow the surrounding file.
- **Formatting**: ktlint (K2 mode, format-on-save in IDEA) for Kotlin; prettier for TS/JSON/YAML/MD; shellcheck for `scripts/*.sh`. `.git-blame-ignore-revs` tracks formatting-only commits — add new bulk-reformat commits there.
- **Always run `./scripts/format.sh` before reporting a task done** whenever TS/JSON/YAML/MD (or Kotlin) files have been touched. The script runs `prettier --write .` and `ktlint --format`, matching what `check-formatting.sh` enforces in CI.
- **Banned dependencies**: `pom.xml` enforces exclusions for vulnerable `bouncycastle` and `xmlunit-core` versions; don't let transitive updates reintroduce them.
- **Keep `infra/README.md` accurate**: any change under `infra/lib/` or `infra/bin/` that affects which stacks exist, what they create, IAM identities, cross-account wiring, manual prerequisites (DNS zones, secrets, KOSKI-side resources), or the Slack/alarms/investigation flow must update `infra/README.md` in the same commit.
